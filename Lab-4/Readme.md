# Лабораторная работа № 4: CI/CD
## Описание проекта
Данный проект реализовывает пайплайн проверки проекта бота погоды в телеграме при пуше.
Проект выполнен на базе:
- **docker** — Развертываение контейнера с веб приложением
- **telebot** —  Библиотека для работы с телеграм ботом
- **GitLab CI** — Автоматизация жизненного цикла ПО
- **HashiCorp Vault** — Хранение токенов

## Как запустить локально
---
### Клонирование репозитория

``` Bash
git clone https://github.com/George1109/ITMO-DevOps-Labs.git
cd Lab-4
```

### Запуск

Настройка секретов
Перед запуском убедитесь, что у вас поднят экземпляр Vault или создайте файл .env:

``` Bash
TELEGRAM_TOKEN=your_token_here
WEATHER_API_KEY=your_api_key_here
```

``` Bash
docker-compose up -d
```

Почему HashiCorp Vault — это красиво??
1. Безопасность — волт является хранилищем, для всех секретов проекта
2. Политики/Пользователи — вы сами решаете кто и что может смотерть/брать/менять - полный контроль
3. Можно настроить appRole, чтобы не только человек мог просматривать секреты, но и программа

Почему хранить секреты в CI/CD переменных не оч??
1. Статичность: Секреты хранятся вечно. Их сложно менять автоматически — приходится заходить в настройки каждого репозитория руками.
2. Риск утечки в логи.
3. Слабый контроль доступа.
4. Отсутствие аудита: Трудно отследить, кто именно, когда и зачем использовал секрет.
5. Дублирование данных: Если один и тот же пароль нужен в пяти разных проектах, его придется копировать в настройки каждого, что создает хаос при обновлении.
6. Человеческий фактор: Секрет в переменных легко забыть обновить или удалить после увольнения сотрудника, создавая «дыру» в безопасности.
